# 仮説と検証結果: Dynamic vs Static チャンク分割

## 最終結論（実験 A〜D 完了後）

> **Dynamic の有利・不利を決めるのは SD（標準偏差）ではなく、  
> 行長の「空間的局在性（ブロック性）」である。**

| 条件 | Dyn/Sta比 | Dynamic の優位性 |
|---|---|---|
| 行長が均一（enwik8, Uniform） | 1.06〜1.12x | **なし** |
| 短/長が**交互分散**（Varied, Extreme） | 1.13〜1.16x | **なし** |
| 短/長が**連続ブロック**（Blocked） | **0.677x** | **あり（+32%）** |

---

## 当初の仮説

### 仮説 1: CPU 前処理のボトルネック

Dynamic の遅さは CPU 前処理（O(n_lines) の文字数スキャン）に起因する。

```
Static の前処理 O(1):
  n_chunks = (n_lines + LPC - 1) / LPC
  for c in range(n_chunks):
      chunk_ls[c] = c * LPC
      chunk_le[c] = min((c+1) * LPC, n_lines)

Dynamic の前処理 O(n_lines):
  total_chars = sum(h_len[i] for i in n_lines)   ← 全行スキャン
  target_chars = total_chars / n_chunks_target
  ← 累積文字数で境界を決定するループ
```

**検証結果**: 部分的に正しい。enwik8（831K行）では前処理差 3.4ms が影響するが、
少行データ（7.6K〜196K行）では差 < 0.1ms で無視できる。

### 仮説 2: 行長のばらつきが大きければ Dynamic が有利

SD が大きいデータでは Static の行数ベース分割で負荷が偏り、Dynamic の文字数均等化が有効になる。

**検証結果**: **誤り（重要な修正）**。  
SD が大きくても、短行と長行が**交互に分散**していれば Static でも自然に均等化される。  
SD は Dynamic の有利性の指標ではない。

---

## 再仮説と確認（実験 D）

### 再仮説: 行長の空間的局在性（ブロック性）が決め手

短行と長行が空間的に集中している（連続ブロックを形成している）場合にのみ、  
Static の連続行割り当てで文字数の大きな不均衡が生じ、Dynamic の恩恵が出る。

### メカニズム

**Static（連続行 LPC=8 ずつ）の挙動:**
- 短行ブロック内チャンク: 8行 × 9文字 = **73 chars/chunk**
- 長行ブロック内チャンク: 8行 × 779文字 = **6,229 chars/chunk**
- 最大不均衡比: **85倍** → GPU ワープでスレッド完了タイミングが大幅にずれる

**Dynamic（文字数均等化）の挙動:**
- 全チャンクが **~274 chars/chunk** に均等化
- GPU スレッドの実行時間がそろい、ワープ効率が向上

### 実験 D 結果

`blocked.txt`（前半: 短行 189K行 / 後半: 長行 6K行）:

| 手法 | 合計(ms) | Dyn/Sta |
|---|---|---|
| Chunk Static | 19.15 | 1.000 |
| **Chunk Dynamic** | **12.97** | **0.677x** |

**仮説確認。Dynamic が Static より 32% 速い。**

## 実用的含意

### Dynamic が有効な場面

- **ログファイル**: ヘッダー行（短い）が先頭に集中し、本文行（長い）が続く
- **コードファイル**: インポート/コメント行（短い）の後に関数定義（長い）が連続
- **Markdown**: 見出し・リスト（短い）と長い本文段落が分離して出現
- **一般化**: ファイル内で「行長の局所性」が高い任意のテキスト

### Dynamic が不要な場面

- Wikipedia のような均一な行長のテキスト
- 短行と長行が均等に混ざった（交互出現の）テキスト
- 行数が少ない（<10K行）データ（GPU Line の方が速い）

### 改善の余地

- Dynamic の CPU 前処理を GPU 側に移植（prefix sum で並列化）することで  
  前処理コストを O(n_lines) → O(log n_lines) に削減できる可能性がある
- 行長の局所性を事前に検出する「アダプティブ切り替え」実装

## 仮説の変遷

```
初期仮説: Dynamic が遅いのは CPU 前処理コスト（O(n_lines)）のため
     ↓ 実験A で部分確認（enwik8 831K行では CPU前処理差=3.4ms が影響）
     ↓ 実験B で反証（少行データでは CPU前処理差 < 0.1ms だが Dynamic は遅い）

修正仮説: SD が大きければ Dynamic が有利
     ↓ 実験B（Varied/Extreme）で反証（SD=434/1355 でも Dynamic は遅い）

再仮説: 行長の空間的局在性（ブロック性）が決め手
     ↓ 実験D（Blocked）で確認（SD=146 だが Dynamic が 32% 速い）

結論: Dynamic の有利性 = 行長の「ブロック性」× 行数の多さ
```
