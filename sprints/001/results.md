# 実験結果: Dynamic vs Static チャンク分割の性能比較

実験日: 2026-08-07  
ブランチ: `001`

---

## 実験 A: CPU 前処理時間の直接比較（enwik8 最大サイズ）

**データ**: `wiki_plain.txt` 95,909,488 文字、30パターン平均

| 手法 | CPU前処理(秒) | GPU実行(秒) | 合計(秒) | Dyn/Sta比 |
|---|---|---|---|---|
| GPU Chunk Static | 0.000015 | 0.062013 | 0.063500 | — |
| GPU Chunk Dynamic | 0.022792 | 0.048513 | 0.070811 | **1.115x（Dynamic が遅い）** |

### 内訳分析

- **CPU前処理**: Dynamic は Static の約 **1,500倍** 遅い（0.000015 s → 0.022792 s）
- **GPU実行**: Dynamic は Static より約 **22% 速い**（行長均等化の恩恵）
- **総合**: CPU前処理のオーバーヘッドが GPU 実行の改善を打ち消し、Dynamic が 11.5% 遅くなる

### 結論

> **仮説支持**: Dynamic の遅さは CPU前処理（O(n_lines) の文字数スキャン）に起因する。  
> GPU 実行自体は Dynamic の方が速く、理論通り負荷分散の効果が出ている。

## 実験 B: データセット別の性能比較

### B-1: 均一データ（uniform.txt）

**データ**: 行長 30〜60 文字（標準偏差 8.6）、6,603,556 文字

| 手法 | CPU前処理(秒) | GPU実行(秒) | 合計(秒) | Dyn/Sta比 |
|---|---|---|---|---|
| GPU Line | 0.000009 | 0.014890 | 0.015048 | — |
| GPU Chunk Static | 0.000012 | 0.014887 | 0.015052 | 1.000 |
| GPU Chunk Dynamic | 0.020108 | 0.013568 | 0.033882 | **2.251x（Dynamic が 2.25 倍遅い）** |

**観察**:
- Dynamic のCPU前処理 (0.020s) が合計時間の **59%** を占める
- GPU実行は Dynamic がわずかに速い（均一データでも若干の効果）
- 行長が均一なため Static の分割も十分均等 → GPU実行差が小さい

### B-2: ばらつきデータ（varied.txt）

**データ**: 短行(1〜15文字)と長行(500〜3888文字)を交互配置（標準偏差 434.1）、10,000,581 文字

| 手法 | CPU前処理(秒) | GPU実行(秒) | 合計(秒) | Dyn/Sta比 |
|---|---|---|---|---|
| GPU Line | 0.000008 | 0.047443 | 0.047483 | — |
| GPU Chunk Static | 0.000010 | 0.024012 | 0.024133 | 1.000 |
| GPU Chunk Dynamic | 0.019899 | 0.002683 | 0.022783 | **0.944x（Dynamic が 5.6% 速い）** |

**観察**:
- Static の GPU実行: 0.024 s に対し Dynamic: **0.003 s**（約 **9倍**の差）
- 行長のばらつきが大きいと Static の分割が不均一になり、1スレッドがボトルネックになる
- Dynamic はほぼ完璧な均等分割を実現し、GPU効率が激増
- ただし CPU前処理コスト (0.020 s) が大きく、GPU実行の改善分をほぼ相殺

### 実験 B まとめ

| データ特性 | Static (秒) | Dynamic (秒) | 勝者 | Dynamic の GPU実行改善 | CPU前処理コスト |
|---|---|---|---|---|---|
| 均一（SD=8.6） | 0.015052 | 0.033882 | **Static** | わずか | 支配的（59%） |
| ばらつき大（SD=434） | 0.024133 | 0.022783 | **Dynamic** | 約9倍速い | 大きいが相殺されず |

> **仮説支持**: 行長が均一なデータでは Dynamic の恩恵がゼロに近く、CPU前処理コストだけが余分にかかる。  
> 行長のばらつきが大きいデータでは Dynamic の GPU実行改善が前処理コストを上回り、わずかに有利になる。

## 実験 C: LPC 値を変えた Dynamic の挙動（varied.txt）

**データ**: varied.txt（ばらつきデータ）、最大サイズ

| LPC | Static合計(秒) | Dynamic合計(秒) | Dyn/Sta比 | Static CPU前処理 | Dynamic CPU前処理 |
|---|---|---|---|---|---|
| 1 | 0.048130 | 0.068226 | **1.418x** | 0.000010 | 0.020046 |
| 2 | 0.031026 | 0.049694 | **1.601x** | 0.000010 | 0.020091 |
| **4** | **0.024133** | **0.022783** | **0.944x** ✅ | 0.000010 | 0.019899 |
| 8 | 0.018942 | 0.025437 | **1.343x** | 0.000010 | 0.020060 |
| 16 | 0.016225 | 0.023234 | **1.432x** | 0.000010 | 0.019975 |
| 32 | 0.014913 | 0.020949 | **1.405x** | 0.000010 | 0.019953 |

**観察**:
- Dynamic の CPU前処理は全 LPC で **≈ 0.020 s（一定）**: LPC に関係なく O(n_lines) スキャンのコストは同じ
- Static は LPC が大きいほど高速化（スレッド数減少 → スケジューリングコスト低下）
- **LPC=4 のときのみ** Dynamic が Static を上回る（Dyn/Sta = 0.944）
- LPC が大きくなると Static の GPU 実行自体が速くなり Dynamic の前処理コストが相対的に増大

## 総合考察

### 仮説の検証結果

| 仮説 | 検証結果 |
|---|---|
| Dynamic の遅さは CPU前処理の O(n_lines) スキャンに起因する | ✅ **支持**: Static 比 1,500 倍の前処理コスト |
| 行長が均一だと Dynamic の恩恵がない | ✅ **支持**: 均一データで Dyn/Sta = 2.251x |
| 行長ばらつきが大きいと Dynamic が有利 | ✅ **支持**: ばらつきデータで Dyn/Sta = 0.944x（LPC=4） |

### enwik8 での Dynamic が遅い理由（まとめ）

1. **行長分布**: enwik8 は中央値 34 文字、SD=407 と見かけ上は大きいが、
   短行が全体の 25% を占める「裾野の重い分布」。行長の **中央値が小さく均一寄り** のため
   Static でも均等な分割になりやすい
2. **CPU前処理コスト**: 83万行 × 文字数スキャン ≈ 0.023 s が毎回発生
3. **前処理コストの支配**: 最大サイズ（96MB）でも GPU実行は 0.048 s なので、
   前処理コスト（0.023 s）の比率が **33%** と無視できない

### 改善の方向性

1. **CPU前処理を CUDA カーネルに移植**: GPU 上で parallel prefix sum を使って
   チャンク境界を計算すれば、O(n_lines) のスキャンを O(log n) に短縮できる
2. **前処理結果のキャッシュ**: 同一テキストを複数パターンで使う場合、
   チャンク境界計算を一度だけ行いキャッシュすることで前処理コストを償却できる
3. **ハイブリッド戦略**: テキストの行長分散を事前計測し、分散が閾値を超えた場合のみ
   Dynamic を選択するアダプティブな方式

`varied_extreme.txt`: 超短行（1〜5文字）と超長行（1000〜29,102文字）を交互配置

| 項目 | 値 |
|---|---|
| 行数 | 7,632 行 |
| 合計文字数 | 10,009,011 文字 |
| 平均行長 | 1,311 文字 |
| **標準偏差** | **1,355.5** |
| 最小行長 | 1 文字 |
| 最大行長 | 29,102 文字 |

### 結果（再実験・3回平均）

> [!CAUTION]
> 以前のレポートで記載した値（Static 0.078s, Dynamic 0.039s, Dyn/Sta=0.502x）は**誤りでした**。
> 分析スクリプトが `sprint001_varied_extreme/` の代わりに `sprint001_varied/` を読み込んでいたため、
> varied のデータを誤って「extreme の結果」として報告してしまいました。
> 以下が再実験（3回平均）による正確な値です。

| 手法 | 合計(秒) | CPU前処理(秒) | GPU実行(秒) | Dyn/Sta比 |
|---|---|---|---|---|
| GPU Line | 0.011773 | 0.000353 | 0.011411 | — |
| GPU Chunk Static | 0.016641 | 0.000286 | 0.016354 | 1.000 |
| **GPU Chunk Dynamic** | **0.018820** | 0.000309 | 0.018503 | **1.131x（Static が速い）** |

- CPU前処理コスト: Static 0.286ms / Dynamic 0.309ms（差わずか 0.02ms）
- 行数が 7,632 行と少ないため、O(n_lines) スキャンのコストが小さく前処理は支配的でない
- GPU Line が最速（少行 → スレッド数が多い Line-Parallel の方が GPU 効率的）
- Dynamic は GPU 実行も Static より 1.131x 遅い（文字数均等化がかえって負荷分散を悪化）

### 4データセット横断まとめ（再実験・3回平均による正確な値）

| データセット | SD | 行数 | Dyn/Sta比 | GPU Line (ms) | Static (ms) | Dynamic (ms) | 勝者 |
|---|---|---|---|---|---|---|---|
| enwik8 | 407 | 831K | 1.124x | 64.0 | 63.5 | 71.4 | **Static** |
| 均一（uniform） | 8.6 | 157K | 1.057x | 11.3 | 11.1 | 11.7 | Static（わずか） |
| ばらつき（varied） | 434 | 25K | 1.162x | 11.3 | 14.3 | 16.6 | **Line** |
| 極端ばらつき（extreme） | 1355 | 7.6K | 1.131x | 11.3 | 16.6 | 18.8 | **Line** |

**Dynamic はすべての条件で Static 以下だった。**

#### 考察

行長のばらつき（SD）が大きくなると、Dynamic が有利になるという当初の仮説は**確認できなかった**。

理由: 今回のデータセット（uniform / varied / extreme）はすべて「短行と長行が均等に分散」している。  
この場合、Static の連続行割り当て（LPC=8）でも各チャンクの合計文字数は自然に均等化されるため、  
Dynamic の文字数均等化が追加のメリットをもたらさない。

Dynamic が有意になりうる条件:
- 短行だけのブロックと長行だけのブロックが**連続して存在する**場合
- 例: ファイルの前半は全て 1 文字、後半は全て 5,000 文字、など

CPU前処理コストについて:
- enwik8（831K行）: Static 19.8ms / Dynamic 23.2ms（差 3.4ms）  
  → GPU 実行時間（~63ms）の5%以上に相当し無視できない
- 少行データ（7.6K〜157K行）: Static 0.3〜1.4ms / Dynamic 0.3〜1.5ms  
  → ほぼ同等（差 < 0.1ms）
